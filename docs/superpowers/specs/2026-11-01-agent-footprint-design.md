# Agent Footprint v0.1 design

Approved direction: the user selected Agent Footprint and explicitly requested building, testing and publishing it. Deliver a useful read-only CLI first; no deletion, process termination, agent config changes, telemetry, servers or API keys.

Python 3.10+ standard library, installable console command `agent-footprint`, `python -m agent_footprint`, and direct `python run.py`. macOS/Linux disk and process inspection; Windows disk inspection with process statistics explicitly unavailable in v0.1. CLI supports --demo (deterministic synthetic data), --format text|json|html, --output new-file, --claude-home / --codex-home explicit roots, --project explicit repeatable worktree roots, --max-files and --timeout budget. Output refuses existing files/symlinks; private POSIX creation. Reports have schema_version and version.

Disk scans metadata only in known Claude and Codex data directories. Never read prompts, transcripts, credentials, environment dumps or file contents. No full-home search. Non-following traversal: skip symlinks, directories replaced by symlinks, special files; directory descent uses no-follow file descriptors where available. Deduplicate hard links across scan categories, report logical bytes and allocated bytes separately (allocated unknown if platform lacks st_blocks). All totals are observed lower bounds when inaccessible/over-budget. Bound file/directory visits and elapsed traversal; keep traversal memory bounded. Redact filenames, usernames, custom paths and project names from all report formats; only fixed source/category names and counters leave collector. Old session files => old observed data, never safe-to-delete. No inference of reclaimable space.

Process collection is optional, POSIX only: bounded ps subprocess of PID, PPID, UID, RSS, CPU and executable name (not full arguments), current UID only. Attribute only explicit executable basenames claude/codex and desktop Claude/Codex; do not assign node/python/browser children without evidence. Related count/RSS sum are selected processes only; shared pages can double-count, CPU is ps-reported not controlled measurement. Command paths never emitted. No orphan certainty from PPID=1. Processes are a momentary snapshot and unavailable states visible.

Explicit project worktree inspection: enumerate only registered worktree counts using `git worktree list --porcelain -z`, with Git subprocess timeout and GIT_OPTIONAL_LOCKS=0. Do not run git status, filters, hooks, fetch or inspect tracked file contents. No branch/path names leave collector. Cap20projects100worktrees and total5 seconds. Counts do not prove work is backed up, inactive or disposable. Reads Git registration metadata only; no guessed age-based deletion decisions.

HTML is a standalone accessible responsive report with no remote assets, no JavaScript required, print-friendly; text and JSON present same evidence/limits. Include aggregate summary, breakdown, source coverage and next actions; user can share after reviewing but redaction is best effort, not anonymity proof. Synthetic demo image clearly labeled. No fake real-world savings or performance percentages.

Tests first: fixture disk tree, symlink escape/root, hard links, sparse files, budget/inaccessible states, no content reads, process attribution parsing without argument disclosure, Git worktree counts with spaces, no output overwrite, HTML escaping, redaction in all formats and demo CLI. Package fresh-install/CLI checks, real local read-only smoke (keep output private), CI Linux/macOS/Windows Python3.10/3.12. MIT original code; no competitor code copied. README clear hook, demo, scope/limits, local-agent prompts, privacy, contribution guide, CI and topics. Publish under user account, relevant tags only, update profile. No PyPI publication assumed.

Review clarifications: missing is not inaccessible; partial counts remain observed lower bounds. Allocated totals are observed file blocks, not unique physical space on APFS clones/compressed filesystems. Windows traversal is best effort and must disclose weaker symlink race guarantees. Name-based process attribution is heuristic. Main CLI bounds traversal with --timeout and subprocesses with separate fixed budgets (5 seconds process + 5 seconds Git); help documents total may exceed traversal timeout.
